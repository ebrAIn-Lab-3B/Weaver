## ebrAIn.lab Weaver 0.1.20

Settings in one place that follows the file that applies, a root file written from a command, and a guide to fitting your own development policy to Weaver.

### What you get

- **The extension** (`weaver-0.1.20.vsix`) for VS Code 1.90 or later.
- **The `weaver` tool** (`weaver.js`, one file for Node 20 or later).

### Start

1. Install the extension: **Extensions**, `…`, **Install from VSIX…**, and pick `weaver-0.1.20.vsix`. It replaces 0.1.19.
2. New to Weaver: [Getting started](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/onboarding/getting-started.md) and [Register your own Project](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/onboarding/register-your-project.md).
3. Follow one piece of work from its start to its end: [Finish one piece of work with Weaver](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/onboarding/dogfooding-round-2.md) ([한국어](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/onboarding/dogfooding-round-2.ko.md)).
4. An AI agent uses [the agent contract](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/onboarding/agent-contract.md).

### What is new

- **One Configuration entry.** The Weaver view and the Overview menu now hold **Open the Overview**, **Configuration**, and **Clone the missing repositories**. Configuration is where every setting is changed: the repositories to show, contributors, the clone folder, and the setup. It also lists the configuration files that can apply here, nearest first: workspace `fabric.yaml`, the root file of the folder, then your personal file. It says which one applies and why the others do not. The entries that only opened a file are gone.
- **Changes follow the file that applies.** Choosing the repositories writes the file that applies, which can be a root file; the change is shown first. A contributor goes to the root file's roster or to your own roster, and each choice says whom it reaches. The editor reads the roster the way the tool does, with your own roster laid over the root file's ([DEC-018](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/decisions/DEC-018-operating-root-configuration.md)).
- **A root file from a command.** `weaver init --root <folder>` and the editor's setup can write the setup file of a folder of projects, after showing it.
- **Your development policy fits Weaver, not the other way round.** Weaver keeps a minimal model: requirements, tasks, and their evidence ([DEC-025](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/decisions/DEC-025-minimal-model-of-a-development-policy.md)). [Work under an operating guideline](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/onboarding/operating-guidelines.md) lists the questions your guideline answers. It also shows how a guideline whose intents live elsewhere (for example in Promises) links them from a requirement.
- **Work before a requirement on the board.** Exploration and other work that comes before a requirement is an ordinary card: an Issue whose title names no task, linking the conversations kept in the repository ([DEC-026](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/decisions/DEC-026-work-before-a-requirement-is-an-ordinary-card.md)). Such an open card can now be finished from the card with **Mark verified**, which closes the Issue after showing that no pull request closed it. A card that names a task is still finished by the pull request that closes it.
- **A card says what it is and what ends it.** It shows its labels other than `status:*` (at most three), so a team can mark a kind of card, such as exploration, with a label of its own. Its pull request line marks the one that closes the Issue ([DEC-022](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/decisions/DEC-022-a-card-carries-its-pull-requests.md)), and an open card that names no task, whose pull requests only refer to it, says "no closing pull request yet".
- **The second-round guide** reads the agentic-base guideline from its default branch.

### Not yet

- User stories on the board, and dragging a card between columns.
- Discussions kept with requirements and tasks.
- Publishing to the VS Code Marketplace or Open VSX.

### Good to know

- **Configuration** has the command title **Weaver: Configuration** (Korean: **Weaver: 설정 관리**), so it is not confused with **Weaver: Set Up**.
- A root file is your own file. Weaver shows a change before writing it and keeps the old file as `config.yaml.bak`. A workspace `fabric.yaml` belongs to a repository, so Weaver only opens it. The sample root file is [here](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/examples/operating-root/.weaver/config.yaml).
- Pages open in VS Code's own browser where it has one: [Finish work inside VS Code](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/onboarding/finish-in-vs-code.md).

## ebrAIn.lab Weaver 0.1.20 (한국어)

설정을 한곳에서 바꾸고 그 변경이 실제로 적용 중인 파일로 가게 했습니다. 폴더 설정 파일을 명령으로 만들 수 있고, 자기 개발 정책을 Weaver에 맞추는 안내가 생겼습니다.

### 받는 것

- **확장**(`weaver-0.1.20.vsix`): VS Code 1.90 이상.
- **`weaver` 도구**(`weaver.js`): Node 20 이상에서 실행하는 파일 하나.

### 시작하기

1. 확장 설치: **확장**, `…`, **VSIX에서 설치…**를 고르고 `weaver-0.1.20.vsix`를 고릅니다. 0.1.19를 대신합니다.
2. Weaver가 처음이면: [시작하기](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/onboarding/getting-started.md), [내 Project 등록하기](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/onboarding/register-your-project.md).
3. 일 하나를 처음부터 끝까지 따라가기: [Weaver로 일 하나 끝내기](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/onboarding/dogfooding-round-2.ko.md).
4. AI 에이전트는 [에이전트 계약](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/onboarding/agent-contract.md)을 따릅니다.

### 새로 된 것

- **설정 관리 하나로.** Weaver 보기와 전체 보기 메뉴에는 **전체 보기 열기**, **설정 관리**, **없는 저장소 클론**만 남았습니다. 보여 줄 저장소, 기여자, 클론 폴더, 설정(Set Up) 다시 하기를 모두 **설정 관리**에서 바꿉니다. 여기서 적용될 수 있는 설정 파일도 가까운 것부터 보여 줍니다. 순서는 워크스페이스 `fabric.yaml`, 폴더의 루트 파일, 개인 파일입니다. 어느 파일이 적용 중이고 나머지는 왜 적용되지 않는지도 알려 줍니다. 파일만 열던 항목은 없어졌습니다.
- **변경은 적용 중인 파일로 갑니다.** 보여 줄 저장소를 고르면 적용 중인 파일에 씁니다. 루트 파일일 수도 있으며, 쓰기 전에 바뀔 내용을 보여 줍니다. 기여자는 루트 파일의 명단이나 내 명단에 넣습니다. 각 명단이 누구에게 적용되는지도 보여 줍니다. 편집기도 도구와 같은 방식으로 명단을 읽습니다. 루트 파일의 명단 위에 내 명단을 겹쳐 읽습니다([DEC-018](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/decisions/DEC-018-operating-root-configuration.md)).
- **루트 파일을 명령으로.** `weaver init --root <폴더>`와 편집기의 설정(Set Up)이 프로젝트 폴더의 설정 파일을 씁니다. 쓰기 전에 내용을 먼저 보여 줍니다.
- **개발 정책을 Weaver에 맞춥니다.** Weaver는 요구사항, 작업, 그 증거만 다루는 최소 모델을 유지합니다([DEC-025](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/decisions/DEC-025-minimal-model-of-a-development-policy.md)). [운영 지침 아래에서 일하기](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/onboarding/operating-guidelines.md)에 지침이 답할 질문을 정리했습니다. 의도가 다른 곳(예: Promise)에 있는 지침이 요구사항에서 그 의도를 어떻게 링크하는지도 보여 줍니다.
- **요구사항 이전 작업도 보드에.** 탐색처럼 요구사항보다 앞선 일은 평범한 카드입니다. 제목이 작업을 가리키지 않는 Issue에 저장소에 보존한 대화를 링크합니다([DEC-026](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/decisions/DEC-026-work-before-a-requirement-is-an-ordinary-card.md)). 이런 열린 카드는 이제 카드의 **검증됨으로 표시**로 끝낼 수 있습니다. Issue를 닫는 PR이 없다는 것을 보여 주고, 확인을 받은 뒤 Issue를 닫습니다. 작업을 가리키는 카드는 지금처럼 Issue를 닫는 PR로 끝납니다.
- **카드가 자기 종류와 끝내는 PR을 보여 줍니다.** `status:*`를 뺀 라벨을 최대 3개까지 보여 줘서, 팀이 탐색 같은 카드 종류를 자기 라벨로 표시할 수 있습니다. PR 줄에는 Issue를 닫는 PR에 **닫는 PR**이 붙고([DEC-022](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/decisions/DEC-022-a-card-carries-its-pull-requests.md)), 작업을 가리키지 않는 열린 카드에 참조만 하는 PR뿐이면 **아직 닫는 PR 없음**이 보입니다.
- **2차 안내서**는 agentic-base 지침을 기본 브랜치에서 읽습니다.

### 아직 없는 것

- 보드에서 사용자 이야기를 다루는 일, 카드를 끌어서 옮기는 일.
- 요구사항과 작업에 대화를 붙여 두는 일.
- VS Code Marketplace, Open VSX 공개.

### 알아 둘 점

- **설정 관리**의 명령 이름은 **Weaver: 설정 관리**입니다. **Weaver: 설정**(Set Up)과 다릅니다.
- 루트 파일은 내 파일입니다. Weaver는 바꾸기 전에 내용을 보여 주고, 이전 파일을 `config.yaml.bak`으로 남깁니다. 워크스페이스 `fabric.yaml`은 저장소의 파일이라 열기만 합니다. 루트 파일 예제는 [여기](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/examples/operating-root/.weaver/config.yaml)에 있습니다.
- 내장 브라우저가 있는 VS Code에서는 페이지가 VS Code 안에서 열립니다: [VS Code 안에서 일 끝내기](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.20/docs/onboarding/finish-in-vs-code.ko.md).
