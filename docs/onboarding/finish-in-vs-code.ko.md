# VS Code 안에서 GitHub 페이지로 일 끝내기

Weaver는 카드, 메뉴, 알림에서 GitHub 페이지(풀 리퀘스트나 Issue)를 열 때 VS Code 안의 탭에 엽니다. 브라우저로 나갔다가 돌아올 필요가 없습니다. 페이지에서 읽고, 댓글을 달고, 합치면, Weaver가 그 결과를 알아채서 전체 보기를 바꿉니다. 이 안내서는 그 동작과 로그인, 탭 위치 설정을 설명합니다. 결정의 근거는 [DEC-020](../decisions/DEC-020-github-pages-open-in-the-built-in-browser.md)에 있습니다(영어). 영어로 된 같은 안내서는 [여기](finish-in-vs-code.md)에 있습니다.

## 어떻게 열리나

- 전체 보기에서 카드를 마우스 오른쪽 버튼으로 눌러 **GitHub의 Issue #번호**나 **풀 리퀘스트**를 고르거나, 요구사항 화면의 `#번호` 링크를 누르면 GitHub 페이지가 새 탭으로 열립니다. 지금 보던 탭 바로 옆에 생깁니다. 요구사항이 연결되지 않은 카드는 그냥 눌러도 Issue 페이지가 열리고, 요구사항이 연결된 카드는 그냥 누르면 요구사항 화면이 열립니다.
- 이 탭은 VS Code의 **내장 브라우저**입니다. 진짜 GitHub 페이지이므로 읽기, 댓글, 검토, 병합을 그 자리에서 모두 할 수 있습니다.
- VS Code에 내장 브라우저가 없으면(오래된 버전) 페이지는 시스템 브라우저로 열립니다. 이것이 정상 동작입니다. 이때도 Weaver는 결과를 알아챕니다.
- 시스템 브라우저로 열고 싶을 때는 카드 메뉴에서 **시스템 브라우저에서 Issue #번호 열기**를 고릅니다.

## 로그인

GitHub 로그인은 이 탭 안의 페이지에서 직접 합니다. Weaver는 자기 토큰을 페이지에 넣지 않고, 페이지의 내용을 읽지도 않습니다. 페이지에서 일어나는 일은 모두 내가 GitHub에서 직접 하는 일입니다.

로그인을 얼마나 기억할지는 VS Code 설정 `workbench.browser.dataStorage`가 정합니다.

| 값 | 로그인을 기억하는 범위 |
| --- | --- |
| `default` (기본) | 내 컴퓨터의 작업 공간은 `global`처럼, 원격 작업 공간은 `workspace`처럼 동작합니다. |
| `global` | 모든 작업 공간이 하나의 로그인을 나눠 씁니다. 한 번 하면 오래갑니다. |
| `workspace` | 같은 작업 공간 안에서만 나눠 씁니다. |
| `ephemeral` | 탭마다 따로입니다. 탭을 닫으면 사라지므로 매번 로그인해야 합니다. |
| `agent` | **쓰지 마세요.** 에이전트가 여는 페이지와 같은 임시 저장소를 나눠 써서, 로그인 정보를 에이전트가 볼 수 있습니다. |

**알아 둘 점이 하나 있습니다.** 신뢰하지 않는 작업 공간(VS Code가 "제한 모드"로 여는 폴더)에서는 이 설정을 무시하고 늘 `ephemeral`로 동작합니다. 그래서 그런 폴더에서는 매번 로그인하게 됩니다. 믿을 수 있는 폴더라면 VS Code에서 작업 공간을 신뢰하도록 설정하세요.

## 탭이 놓이는 곳

탭이 놓일 자리는 VS Code 설정 `workbench.browser.newTabPlacement`가 정합니다. Weaver는 칸을 정하지 않습니다.

| 값 | 탭이 열리는 곳 |
| --- | --- |
| `activeGroup` (기본) | 지금 쓰는 편집기 칸입니다. 보던 탭 바로 옆에 열립니다. |
| `sideGroup` | 옆에 따로 둔 칸입니다. 다음 탭도 같은 칸에 열리고, 그 칸에는 다른 편집기가 열리지 않습니다. 전체 보기를 한쪽에 두고 PR 페이지를 다른 쪽에 모으고 싶다면 이 값이 좋습니다. |
| `window` | 따로 둔 새 창입니다. 다음 탭도 그 창에 열립니다. |

## 열고 난 뒤 Weaver가 하는 일

Weaver가 연 풀 리퀘스트나 Issue 페이지는 Weaver가 계속 지켜봅니다. 결과는 GitHub에서 읽어 옵니다. 읽는 때와 그치는 때는 이렇습니다.

- 페이지를 연 직후 한 번 읽습니다. 이 첫 읽기는 비교할 기준만 정하고 알림은 내지 않습니다.
- VS Code 창이 앞에 있을 때 약 1분마다 읽습니다. 다른 창에 갔다가 돌아오면 바로 읽습니다. 다만 10초 안에 다시 읽지는 않습니다.
- 연 지 10분이 지나면 그칩니다. 병합되거나 닫혀도 그칩니다.
- 창이 뒤에 있을 때는 읽지 않습니다. 그래서 GitHub에 요청을 쓸데없이 보내지 않습니다.

무엇이 바뀌었는지는 화면 아래 상태 표시줄에 10초 동안 알려 줍니다.
- 병합: "…의 풀 리퀘스트 #번호이(가) 병합됐습니다."
- 병합 없이 닫힘: "…의 풀 리퀘스트 #번호이(가) 병합 없이 닫혔습니다."
- Issue 닫힘: "…의 Issue #번호이(가) 닫혔습니다."
- 검사 결과가 바뀜: "…의 풀 리퀘스트 #번호의 검사: 통과." (진행 중, 실패, 통과 가운데 하나)

알림과 함께 전체 보기가 Project를 다시 읽습니다. 그래서 돌아왔을 때 카드가 이미 제자리에 있습니다. 읽을 때는 VS Code에 이미 있는 GitHub 로그인을 조용히 씁니다. 새로 로그인하라고 묻지 않고, 로그인이 없으면 읽지 않습니다.

## 직접 해 보기

이 일은 5분이면 됩니다. 열려 있는 PR이 하나 필요합니다. 그 PR이 가리키는 Issue의 카드가 전체 보기에 있어야 합니다(PR 본문의 `Closes #번호`나 `Refs #번호`로 가리킵니다).

1. 전체 보기에서 그 카드를 마우스 오른쪽 버튼으로 누르고 **풀 리퀘스트**를 고릅니다. PR이 여러 개면 하나를 고릅니다.
2. PR 페이지가 지금 보던 탭 바로 옆에 열립니다. 처음이면 이 탭에서 GitHub에 로그인합니다.
3. PR이 만들어진 지 얼마 안 되어 검사가 돌고 있다면, 화면 아래에 "검사: 진행 중"에서 "검사: 통과"로 바뀌는 알림이 뜹니다. 보통 1분 안에 뜹니다.
4. **연 지 10분 안에** 탭에서 PR을 병합합니다.
5. 1분 안에 상태 표시줄에 "풀 리퀘스트 #번호이(가) 병합됐습니다"가 뜨고, 전체 보기의 카드가 바뀝니다. 병합하고 나서 다른 창에 갔다가 돌아오면 더 빨리 뜹니다.
6. 알림을 놓쳤다면 로그에서 확인할 수 있습니다. 아래쪽 패널에서 **Output**을 열고, 오른쪽 드롭다운에서 **Weaver**를 고릅니다. 이런 줄이 있어야 합니다.

   ```text
   page ebrain-lab-3b/weaver|pull|251: open/passing -> merged/-
   ```

   줄의 뜻은 "저장소|풀 리퀘스트|번호: 이전 상태/검사 -> 새 상태/검사"입니다.

## 알아 둘 한계

- 지켜보는 것은 **Weaver가 연 페이지**뿐입니다. 브라우저에서 내가 직접 열어 병합한 PR은 알아채지 못합니다. 그때는 전체 보기에서 **새로 고침**을 누르세요.
- 연 지 10분이 지난 뒤에 병합하면 알림이 오지 않습니다. 새로 고침을 누르세요.
- PR이 Issue를 닫아도 `status:verified` 라벨은 저절로 붙지 않습니다. 닫힌 카드에 "닫혔지만 status:verified 라벨이 없습니다(검증 공백)"라는 경고가 뜨면 Issue에 라벨을 직접 붙여 주세요. 아직 고치지 못한 불편입니다.
- 10분과 1분은 첫 추정치입니다. 쓰면서 더 맞는 값이 보이면 알려 주세요.

## 막혔을 때

| 이런 일이 생기면 | 이렇게 해 보세요 |
| --- | --- |
| 페이지가 VS Code 안이 아니라 시스템 브라우저로 열림 | 이 VS Code에 내장 브라우저가 없는 경우입니다. 정상 동작입니다. |
| 열 때마다 GitHub에 로그인하라고 함 | `workbench.browser.dataStorage`가 `ephemeral`이거나, 신뢰하지 않는 작업 공간이라서입니다. 위의 로그인 절을 보세요. |
| 병합했는데 알림이 안 옴 | 연 지 10분이 지났거나, VS Code 창이 뒤에 있었거나, 페이지를 Weaver가 열지 않은 경우입니다. 전체 보기에서 **새로 고침**을 누르세요. |
| 전체 보기에서 **풀 리퀘스트**를 골랐는데 "이 Issue를 가리키는 풀 리퀘스트가 없습니다"라고 나옴 | PR 본문에 `Closes #번호` 또는 `Refs #번호`가 있는지 봅니다. |
| 새 탭이 다른 칸에 열려서 불편함 | `workbench.browser.newTabPlacement`를 `activeGroup`(기본)으로 돌립니다. |
| 로그에 읽기 실패 줄(`could not be read`)이 보임 | GitHub 로그인이 만료됐거나 네트워크 문제입니다. 전체 보기에서 **GitHub에 로그인**을 다시 누르세요. |
