# Weaver로 일 한 건을 끝까지 해 보기 (2차)

우리가 만든 도구를 우리가 직접 써 보는 일을 도그푸딩이라고 부릅니다. [1차 안내서](dogfooding-round-1.md)는 설치하고, 설정하고, 전체 보기를 여는 데까지였습니다. 이번 2차는 일 한 건이 시작되어 끝나는 모습을 처음부터 끝까지 따라가 봅니다. 영어로 된 같은 안내서는 [여기](dogfooding-round-2.md)에 있습니다.

따라 하다가 막히거나 불편하면 거기서 멈추고 [끝의 방법](#불편한-점-알리기)대로 알려 주세요. 목록을 끝까지 따라 하지 않아도 됩니다. 막힌 곳이 바로 우리가 고쳐야 할 곳입니다.

## 준비물

- VS Code 1.90 이상
- Project와 저장소를 읽고 쓸 수 있는 GitHub 계정
- 터미널 도구를 쓰려면 Node.js와, 로그인해 둔 GitHub 명령줄 도구(`gh`)

## 1. 설치

1. [최신 릴리즈](https://github.com/ebrAIn-Lab-3B/Weaver/releases)에서 `weaver-<버전>.vsix`와 `weaver.js`를 내려받습니다.
2. VS Code의 확장 화면에서 `…`를 누르고 **VSIX에서 설치…** 를 골라 파일을 지정합니다(영어 화면에서는 *Install from VSIX…*).
3. 예전에 `palab.weaver`라는 확장을 설치했다면 먼저 지웁니다. 이름이 바뀌어서, 두 개가 함께 보일 수 있습니다. 새 확장은 `ebrain-lab.weaver`입니다.
4. VS Code를 다시 불러옵니다(명령 팔레트에서 *Developer: Reload Window*). 왼쪽 막대에 **Weaver** 아이콘이 보이면 됩니다.

터미널 도구는 따로 설치하지 않습니다. 내려받은 `weaver.js`를 `node weaver.js <명령>`으로 실행합니다. 아래 예에서는 `weaver`라고만 줄여 씁니다.

## 2. 설정

1차 안내서의 2번과 같습니다. 명령 팔레트에서 **Weaver: 설정**을 실행하고, GitHub에 로그인하고, 보여 줄 Project를 고릅니다. 마지막에 파일 내용이 나오면 읽어 본 뒤 **쓰기**를 누릅니다. 이 파일은 내 컴퓨터에만 생기고, 어느 저장소에도 올라가지 않습니다.

프로젝트를 모아 둔 폴더마다 설정을 따로 두고 싶다면 그 폴더 안에 `.weaver/config.yaml`을 만듭니다. 예제와 설명은 [Project 등록하기](register-your-project.md)에 있습니다.

조직이 정해 둔 일하는 방식(운영 지침)이 있다면 같은 파일에 `guideline` 한 줄을 적습니다. 그러면 process 파일이 없는 저장소에 그 지침으로 시작 파일을 제안해 줍니다. 자세한 내용은 [운영 지침으로 일하기](operating-guidelines.md)에 있습니다(영어).

## 3. 전체 보기에서 저장소 살펴보기

1. Weaver 아이콘을 누르고 **전체 보기 열기**를 고릅니다.
2. 저장소마다 한 줄씩 줄(레인)이 있고, 카드가 백로그, 준비됨, 진행 중, 막힘, 검토, 검증됨 열에 나뉘어 있습니다.
3. 저장소 이름 아래에 `지침: …` 한 줄이 보이면, 그 저장소에 적용되는 지침입니다. 지침이 없으면 이 줄은 나오지 않습니다.
4. **process 파일 시작하기** 버튼이 있는 저장소는 아직 process 파일이 없는 저장소입니다. process 파일은 그 저장소가 일을 어떻게 관리하는지 적어 둔 `.weaver/process.yaml`입니다.

## 4. process 파일이 없는 저장소에 시작 파일 만들기

1. 레인의 **process 파일 시작하기**를 누릅니다.
2. 확인 창에 만들 파일의 내용이 전부 나옵니다. 어느 지침에서 왔는지(지침이 없으면 기본값)도 함께 나옵니다. 읽어 보세요.
3. 괜찮으면 **풀 리퀘스트 열기**를 누릅니다. 풀 리퀘스트(PR)는 고친 내용을 합쳐 달라는 요청입니다. 취소하면 아무것도 올라가지 않습니다.
4. PR이 열렸다는 알림이 뜨면 **보기**를 누릅니다. PR 화면이 VS Code 안의 새 탭에 열립니다.

이렇게 되어야 합니다.
- 기본 브랜치에는 아무것도 쓰이지 않고, PR만 생깁니다.
- 팀이 PR을 검토한 뒤에 합쳐야 파일이 적용됩니다.

터미널에서는 `weaver process start --repository 소유자/저장소`로 같은 일을 합니다. 이 명령은 먼저 계획만 보여 줍니다. 계획에 나온 번호를 `--approve 번호`로 넣어 다시 실행해야 PR이 올라갑니다.

## 5. 작업 한 건 만들기

일 한 건은 요구사항에 딸린 작업으로 만듭니다. 터미널에서 이렇게 합니다.

```bash
weaver task create --title "짧은 제목" --requirement REQ-번호 --criteria AC-번호
```

- 제목에는 쌍점(`:`)이나 줄바꿈을 쓸 수 없습니다.
- 이 명령은 먼저 계획을 보여 줍니다. 계획은 세 가지입니다. GitHub에 Issue(일감 항목)를 만들고, Project에 카드를 올리고, 작업 파일을 담은 PR을 엽니다.
- 계획을 읽고 괜찮으면, 나온 번호들을 `--approve 번호,번호,번호`로 넣어 다시 실행합니다.

잠시 뒤 전체 보기를 새로 고치면 백로그에 새 카드가 보입니다.

## 6. 일하고 증거 남기기

1. 일을 마친 PR의 본문에 `Closes #Issue번호`를 적습니다. PR이 합쳐지면 Issue가 저절로 닫힙니다.
2. 카드는 닫힌 Issue를 "검증됨"으로 봅니다. 다만 합쳐진 PR 중에 그 Issue를 닫는 것이 없으면, 카드에 "이 Issue를 닫는 병합된 PR이 없습니다"라는 표시가 붙습니다.
3. 카드를 다른 열로 옮기려면 `weaver card move 카드 --to 열이름`을 씁니다. 이 명령도 먼저 무엇을 바꿀지 보여 주고, 승인해야 바꿉니다.

## 7. VS Code 안에서 끝내기

1. 전체 보기에서 카드를 마우스 오른쪽 버튼으로 누르고 **풀 리퀘스트**를 고릅니다. PR이 여러 개면 하나를 고릅니다.
2. PR 화면이 지금 보던 탭 바로 옆에 새 탭으로 열립니다. GitHub에 로그인하라고 하면 이 탭 안에서 합니다. 한 번 해 두면 한동안 기억합니다.
3. 이 탭에서 PR을 읽고, 댓글을 달고, 합칩니다.
4. 다른 창에 갔다가 돌아오거나 1분쯤 기다리면, 화면 아래 상태 표시줄에 "풀 리퀘스트 #번호이(가) 병합됐습니다"가 뜹니다. 전체 보기의 카드도 알아서 바뀝니다.

VS Code 안에서 열지 않고 시스템 브라우저로 열고 싶다면, 카드 메뉴에서 **시스템 브라우저에서 Issue #번호 열기**를 고릅니다.

## 8. 마무리 점검

```bash
weaver reconcile
```

처리할 것이 없다고 나오면 보드와 파일이 서로 맞는 것입니다. 무엇을 고쳐야 한다고 나오면 계획을 읽어 보고, 괜찮으면 `--approve`로 승인합니다.

**알려진 불편이 하나 있습니다.** PR이 Issue를 닫아도 `status:verified` 라벨은 저절로 붙지 않습니다. 닫힌 카드에 "닫혔지만 status:verified 라벨이 없습니다"라는 경고가 뜨면, Issue에 그 라벨을 직접 붙여 주세요. 아직 고치지 못한 불편입니다. 겪으면 알려 주세요.

## 불편한 점 알리기

[피드백 양식](https://github.com/ebrAIn-Lab-3B/Weaver/issues/new?template=dogfooding-feedback.yml)을 엽니다. 네 가지를 묻습니다. 무엇을 하려 했는지, 어떻게 되기를 바랐는지, 실제로 어떻게 되었는지, 일하는 데 얼마나 걸림돌이었는지입니다. 화면 사진이 있으면 도움이 됩니다. 짧아도 괜찮습니다.

## 막혔을 때

| 이런 일이 생기면 | 이렇게 해 보세요 |
| --- | --- |
| 전체 보기가 비어 있고 "설정이 없다"고 나옴 | 2번의 설정을 다시 합니다. |
| "project" 권한이 없다고 나옴 | **GitHub에 로그인**을 다시 눌러 `project` 권한을 허락합니다. |
| 확장이 두 개 보임(`palab.weaver`와 `ebrain-lab.weaver`) | 예전 것(`palab.weaver`)을 지우고 VS Code를 다시 불러옵니다. |
| PR이 열려야 하는데 외부 브라우저가 열림 | 이 VS Code에 내장 브라우저가 없는 경우입니다. 시스템 브라우저로 열리는 것이 정상 동작입니다. |
| 카드에서 **풀 리퀘스트**를 골랐는데 "이 Issue를 가리키는 풀 리퀘스트가 없습니다"라고 나옴 | PR 본문에 `Closes #Issue번호` 또는 `Refs #Issue번호`가 있는지 봅니다. |
| `weaver task create`가 제목 때문에 멈춤 | 제목에서 쌍점(`:`)을 뺍니다. |
| 시작 파일 PR이 "이미 열려 있다"며 거절됨 | 열려 있는 PR(`docs/weaver-process-file`)을 합치거나 닫은 뒤 다시 합니다. |

## Weaver가 하지 않는 일

Weaver는 무엇을 바꿀지 보여 주고 승인을 받기 전에는 카드, 라벨, 파일을 바꾸지 않습니다. 읽기만 하는 동안에는 아무것도 바뀌지 않습니다.
