## ebrAIn.lab Weaver 0.1.19

The first official release. Weaver connects requirements, tasks, people, AI agents, code, pull requests, and tests across the repositories of a team, and shows where each piece of work stands on a board.

### What you get

- **The extension** (`weaver-0.1.19.vsix`) for VS Code 1.90 or later: the Overview board across your repositories, and a requirement view for each requirement.
- **The `weaver` tool** (`weaver.js`, one file for Node 20 or later): the same board for a terminal or an AI agent. A write is shown first and happens only after it is approved.

### Start

1. Install the extension: **Extensions**, `…`, **Install from VSIX…**, and pick `weaver-0.1.19.vsix`.
2. Point Weaver at your own GitHub Project and say how your repositories track their work: [Getting started](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.19/docs/onboarding/getting-started.md) and [Register your own Project](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.19/docs/onboarding/register-your-project.md).
3. Follow one piece of work from its start to its end: [Finish one piece of work with Weaver](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.19/docs/onboarding/dogfooding-round-2.md) ([한국어](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.19/docs/onboarding/dogfooding-round-2.ko.md)).
4. An AI agent uses [the agent contract](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.19/docs/onboarding/agent-contract.md).

### What it does

- **The Overview**: the cards of a GitHub Project of your own, a lane for each repository, six columns, with the reason for each gap (no evidence, no status label, idle for long).
- **Pull requests on the card**: each card shows the pull requests that refer to its Issue, open first. Press one and the GitHub page opens in a tab of VS Code. When it is merged or closed, the Overview updates by itself.
- **Finishing in VS Code**: the page opens in VS Code's own browser, so you review and merge without leaving the editor. Where VS Code has no built-in browser, the system browser is used.
- **Mark verified from the card**: a finished card offers a button that shows what will change and asks before it writes.
- **A card without a task file says where the file is**: Weaver asks GitHub. If the file is there and your folder is behind, **Update the folder** brings it up to date (only by a fast-forward, only on the default branch, only when you have no change of your own). If there is no file, **Make the task file** opens a pull request that adds it. Both show what they will do and ask first.
- **One setup file for a folder of projects**, and a personal one, and a roster of the people and agents you work with.
- **How a repository tracks its work**: a process file in the repository (columns, evidence, idle days, the fields of a task). A repository without one is offered a starting file, from your organization's operating guideline when there is one. The offer is a pull request, shown in full first.
- **The `weaver` tool**: list and show cards, create a task, move a card, attach evidence, reconcile the board with the files, start a process file, add Issues to the Project.
- **English and Korean** in the extension and the tool.

### Not yet

- User stories on the board, and dragging a card between columns.
- Discussions kept with requirements and tasks.
- Publishing to the VS Code Marketplace or Open VSX.
- Writing the setup file of a folder with a command (copy the [sample](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.19/examples/operating-root/.weaver/config.yaml)).

### Good to know

- The board reads your GitHub sign-in in VS Code (scopes `repo` and `project`). The terminal tool uses `gh auth login` with the same scopes.
- A card finds its requirement through the files in the folder you have open. If a card opens its Issue and says there is no task file, the card says where the file is and offers the button for it; the folder is updated only when it is on the default branch with nothing of yours changed, and otherwise `git pull` is yours to run.
- Pages open with the sign-in you make in VS Code's browser tab. How long it is kept is a VS Code setting (`workbench.browser.dataStorage`); the guide [Finish work inside VS Code](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.19/docs/onboarding/finish-in-vs-code.md) explains it.

## ebrAIn.lab Weaver 0.1.19 (한국어)

첫 공식 릴리즈입니다. Weaver는 팀의 여러 저장소에 흩어진 요구사항, 작업, 사람, AI 에이전트, 코드, 풀 리퀘스트, 테스트를 이어 주고, 일마다 어디까지 왔는지를 보드에 보여 줍니다.

### 받는 것

- **확장**(`weaver-0.1.19.vsix`): VS Code 1.90 이상. 저장소 전체를 가로지르는 전체 보기(Overview)와 요구사항마다의 요구사항 화면이 있습니다.
- **`weaver` 도구**(`weaver.js`, Node 20 이상에서 실행하는 파일 하나): 같은 보드를 터미널이나 AI 에이전트가 씁니다. 무엇을 바꿀지 먼저 보여 주고, 승인해야 바꿉니다.

### 시작하기

1. 확장을 설치합니다. **확장** 화면에서 `…`를 누르고 **VSIX에서 설치…** 를 골라 `weaver-0.1.19.vsix`를 지정합니다.
2. 내 GitHub Project를 가리키고, 저장소가 일을 어떻게 관리하는지 정합니다. [시작하기](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.19/docs/onboarding/getting-started.md)와 [Project 등록하기](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.19/docs/onboarding/register-your-project.md)를 보세요(영어).
3. 일 한 건을 처음부터 끝까지 따라가 봅니다: [Weaver로 일 한 건을 끝까지 해 보기](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.19/docs/onboarding/dogfooding-round-2.ko.md).
4. AI 에이전트는 [에이전트 계약](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.19/docs/onboarding/agent-contract.md)을 따릅니다(영어).

### 할 수 있는 일

- **전체 보기**: 내 GitHub Project의 카드를 저장소마다 한 줄씩, 여섯 열로 보여 주고, 어긋난 곳(증거 없음, 상태 라벨 없음, 오래 멈춤)의 이유를 알려 줍니다.
- **카드에 풀 리퀘스트 표시**: 카드의 Issue를 가리키는 풀 리퀘스트가 카드에 보이고, 열린 것이 먼저입니다. 누르면 GitHub 페이지가 VS Code 안의 탭으로 열립니다. 병합되거나 닫히면 전체 보기가 알아서 바뀝니다.
- **VS Code 안에서 끝내기**: VS Code의 내장 브라우저로 열려서, 편집기를 떠나지 않고 검토하고 병합합니다. 내장 브라우저가 없는 VS Code에서는 시스템 브라우저로 엽니다.
- **카드에서 검증됨으로 표시**: 끝난 카드에 버튼이 나옵니다. 무엇이 바뀌는지 보여 주고, 쓰기 전에 묻습니다.
- **작업 파일이 없는 카드는 파일이 어디 있는지 알려 줍니다**: Weaver가 GitHub에 물어봅니다. 파일이 GitHub에 있고 내 폴더가 뒤처져 있으면 **폴더 최신으로 받기**가 폴더를 앞으로 옮깁니다(빨리 감기만, 기본 브랜치에서만, 내가 바꾼 것이 없을 때만). 파일이 어디에도 없으면 **작업 파일 만들기**가 파일을 추가하는 풀 리퀘스트를 엽니다. 둘 다 하려는 일을 먼저 보여 주고 묻습니다.
- **하나의 설정 파일로 폴더마다 설정 파일**, 개인 설정 파일, 함께 일하는 사람과 에이전트의 명단.
- **저장소가 일을 관리하는 방식**: 저장소 안의 process 파일(열, 증거, 멈춤 기준, 작업의 필드). process 파일이 없는 저장소에는 조직의 운영 지침이 있으면 그 지침에서, 없으면 기본값으로 시작 파일을 제안합니다. 제안은 풀 리퀘스트이고, 먼저 내용을 전부 보여 줍니다.
- **`weaver` 도구**: 카드 목록과 상세, 작업 만들기, 카드 옮기기, 증거 붙이기, 보드와 파일 맞추기(reconcile), process 파일 시작, Project에 Issue 올리기.
- **영어와 한국어**를 확장과 도구가 함께 지원합니다.

### 아직 없는 것

- 보드에서 사용자 이야기를 다루는 일, 카드를 끌어서 옮기는 일.
- 요구사항과 작업에 대화를 붙여 두는 일.
- VS Code Marketplace, Open VSX 공개.
- 폴더의 설정 파일을 명령으로 만드는 일(대신 [예제](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.19/examples/operating-root/.weaver/config.yaml)를 복사해 고칩니다).

### 알아 둘 점

- 보드는 VS Code의 GitHub 로그인(`repo`, `project` 권한)으로 읽습니다. 터미널 도구는 같은 권한으로 `gh auth login`을 합니다.
- 카드는 열어 둔 폴더의 파일로 요구사항과 이어집니다. 카드가 요구사항 대신 Issue를 열고 "작업 파일이 없다"고 하면 폴더를 최신으로 받으세요(`git pull`).
- 페이지는 VS Code 브라우저 탭에서 한 로그인으로 열립니다. 로그인을 얼마나 기억할지는 VS Code 설정(`workbench.browser.dataStorage`)입니다. [VS Code 안에서 일 끝내기](https://github.com/ebrAIn-Lab-3B/Weaver/blob/v0.1.19/docs/onboarding/finish-in-vs-code.ko.md)에 설명이 있습니다.
