## Independent test evidence: decision for review

REQ-024 asks the diagnostic to distinguish independent test evidence, while REQ-023 requires an established producer contract before free text becomes authoritative. The current implementation can show attributed claims and linked CI facts, but cannot determine an independent executor from a shared GitHub account or a bare comment. A portable producer and trust policy are not specified here.

Options for a later reviewed decision are: (1) keep linked claims explicitly unverified and require a person to inspect the source; (2) let a repository configure an existing evidence producer and verifier, including the source, subject revision, actor identity, execution result and read-time provenance; or (3) define a portable producer contract only after comparing real producers. In every option, an assertion alone is not proof of independent execution, an unavailable or incomplete source remains unknown, and a record for another revision is not current. A configured verifier would establish only the guarantees of that verifier, not human independence by account name. No option is accepted by this note, and no change to Verified policy or automatic writes is authorized by it. The owner must decide the producer, identity and trust guarantees before implementing an authoritative classification; TASK-137 remains in progress until its acceptance criteria are reviewed against that decision.

### Reviewable minimum for a configured evidence source

A proposed read-only adapter would return an observation containing the source URL and read time, source completeness or error, the subject repository and exact revision, the producer's authenticated identity and its claimed executor, the test command or run identifier, result, and a link to the original run or artifact. These are candidate fields for discussion, not a new accepted schema. Weaver would display separately (a) source reachability and record validity, (b) the producer's attributed claim, (c) whether the recorded revision matches the current target, and (d) whether the organization's configured verifier can establish the claimed execution. Independence would remain unknown unless that verifier's explicitly configured guarantees support it; account names or two comments alone are insufficient. Missing revision, partial reads, unverifiable actor identity, conflicting observations or a changed revision must stay unresolved. No result would mark a task Verified or authorize a write.

Before implementing this option, compare at least two existing producers, establish whether they can supply these facts and authenticate their source, define how a repository selects and trusts a verifier without a PALab-specific default, and test unavailable sources, changed revisions, disagreement and spoofed identities. If no producer satisfies the contract, continue showing attributed unverified records. This is a decision proposal only; it does not alter current configuration, evidence policy, or TASK-137 completion criteria.
